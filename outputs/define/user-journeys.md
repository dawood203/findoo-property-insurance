# User Journeys

**Evidence status:** BRD-implied journey definitions, not observed journeys or usability-test results.

| Journey | BRD-defined flow | User outcome | Requirements |
|---|---|---|---|
| Obtain understandable cover | Select need → read plain-language overview → complete/correct details → receive verified quote or manual-review route → compare material differences → save, seek help or proceed through approved purchase flow. | Understand material differences and proceed, save or ask for help without losing work. | BRD-001–BRD-012, BRD-025–BRD-029 |
| Start and progress a claim | Start claim → safety guidance → report incident → submit available evidence → receive reference/next action → track/answer requests → contact support → view documented decision when issued. | Submit complete or clearly incomplete package, identify owner/next action and obtain human help without restarting. | BRD-013–BRD-023, BRD-025–BRD-029 |
| Resolve a support issue | Open contextual help → select channel or callback/case request → receive reference/response information when available → view history and escalation route. | Reach correct team without repeating unnecessary details. | BRD-021–BRD-024, BRD-027, BRD-029, BRD-031 |

**Unresolved:** Exact stage names, ownership, expected update windows, support SLA, channels and escalation rules require stakeholder confirmation. (OQ-06–OQ-08.)
