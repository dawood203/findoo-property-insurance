# Skill: UI Specification

**Objective:** Describe interfaces and interaction states that implement approved IA and requirements.

**Required inputs:** Approved IA, definition, requirement matrix, approved content/rules and device constraints.

**Execution steps:**

1. Identify screens/states per task flow.
2. Specify component behavior, inputs, validation, recovery, disclosures and support routes.
3. Annotate responsive and interruption states.
4. Link each decision to requirement IDs or mark as proposal.

**Output format:** Annotated screen/prototype set plus screen-state specification and trace map.

**Quality checklist:** Covers required information, error recovery, save/resume and integration-unavailable states where applicable; provenance is visible for constrained content.

**Restrictions:** Do not claim accessibility/legal approval, create unapproved guarantees, or replace policy wording with a design interpretation.
