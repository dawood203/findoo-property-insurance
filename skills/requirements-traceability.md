# Skill: Requirements Traceability

**Objective:** Maintain a verifiable link between BRD requirements and downstream artifacts.

**Required inputs:** BRD, existing requirement matrix, phase artifacts and decision log.

**Execution steps:**

1. Retain existing BRD IDs and original references.
2. Add source, type, priority, UX impact, dependencies, confidence and open questions for each requirement.
3. Link derived artifacts to one or more requirement IDs or document why no BRD requirement applies.
4. Update validation/disposition only with evidence.

**Output format:** Markdown matrix with one requirement per row and evidence links.

**Quality checklist:** Unique IDs; complete mandatory columns; valid source references; no unsupported satisfied status.

**Restrictions:** Do not renumber requirements, manufacture dependencies, or use traceability as proof of approval.
