# Skill: Accessibility Review

**Objective:** Assess designs against the confirmed accessibility target and flag unresolved compliance scope.

**Required inputs:** UI specification, confirmed target standard if available, supported-device matrix.

**Execution steps:**

1. Confirm the applicable standard; if absent, log it as blocking/unknown.
2. Review structure, labels, keyboard flow, focus, contrast, errors, media and responsive behavior.
3. Record evidence, findings, severity and owner.
4. Distinguish a design review from formal accessibility certification.

**Output format:** Checklist with evidence, findings, status and unresolved questions.

**Quality checklist:** Every conclusion has observed evidence; missing standard is conspicuous; error recovery and support paths are reviewed.

**Restrictions:** Do not certify legal compliance or accessibility without authorized testing and scope.
