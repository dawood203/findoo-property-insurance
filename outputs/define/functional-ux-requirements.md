# Functional UX Requirements

**Validation basis:** Each item reproduces an approved Research trace ID and is validated against the BRD matrix. No requirement is marked implemented or approved for build.

| Trace ID | Functional UX requirement | Stated priority |
|---|---|---|

| BRD-002 | Start, save, resume and review an application. | Must |
| BRD-003 | Ask only approved-underwriting-required information and explain unfamiliar/sensitive requests. | Must |
| BRD-004 | Where permitted, prefill approved property data, identify source and permit correction. | Should |
| BRD-005 | Validate inputs and provide specific accessible error recovery. | Must |
| BRD-006 | Route manual-underwriting cases without unsupported instant decisions. | Must |
| BRD-007 | Show only verified eligible options from approved pricing/underwriting source. | Must |

| BRD-009 | Explain consequences of deductible, limit or optional-cover changes before selection. | Must |
| BRD-010 | Show discounts/cost-reduction options only when eligibility and terms are verified. | Should |
| BRD-011 | Provide authenticated policy information and approved servicing actions. | Must |
| BRD-012 | Do not make cheapest/best/guaranteed-approval claims without lawful substantiation. | Must |
| BRD-013 | Provide discoverable claim start plus approved alternate verification where needed. | Must |
| BRD-014 | Provide emergency guidance and distinguish emergency from insurance support. | Must |

| BRD-024 | Capture service feedback without blocking completion. | Could |
